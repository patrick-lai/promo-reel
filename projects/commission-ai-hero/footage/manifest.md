# commission-ai-hero: footage notes

`manifest.yaml` is authoritative (path, sha256, app commit, capture URL/params, framing, DPR, ...); this file is for humans and for the
capturing agent. **Raw media is never committed** (no LFS): it lives on the box at the absolute `path` in the manifest.
`promo build|shot|check` verify every referenced clip's sha256 and fail if it is missing or changed. Table below is generated by
`promo footage add`; run `promo footage verify` any time.

## Where these clips came from
- Source drop: `/workspace/videos/commission-ai-promo/footage/` (original notes: `manifest.md` and `capture-log.jsonl` there, plus `v1-1080/capture-log.jsonl`).
- App commits: `0a3c3acdb5871f22808fe95168962fb98d46a450` (origin/main, 1 Oct 2026); `bc10d245349b5c545af54057e55dade8e431c64f`
  (branch `promo/demo-scenario`, PR #86, unmerged; adds the `?demo=promo` scenario, used for shots 05, 11, 15, 16a);
  `4a427fc05f829d7b2e4ed7ea642d77340554f7f8` (main, 3 Oct 2026; shot 10 recapture).
- Legacy takes: 3840x2160 @ 60 fps, 1920x1080 CSS px at DPR 2, lossless H.264 (yuv444p), Playwright clock stepped 1/60 s, dark theme.
- Shot 10 (`shot-10-v1080`) is 1920x1080 at DPR 1: its ~3x push-in is a soft upscale (the check gate warns). Recapture at DPR 2.
- Everything here is **demo-mode** footage (`?demo=...`); the check gate reports it as a WARN.
- Shot 17 reuses the shot-01 file (identical bytes), hence the same sha256 for `shot-01-v1` and `shot-17-v1`.
- The `-v1` suffix on some files is not explained in the capture log; the log entry is matched by shot name.
- Unused so far: `v1-1080/shot-03-night.mov` (night Workshop plate, commit 4a427fc0) could feed `plates: {night: {source: ...}}`.

## How to add or replace a clip
```
promo -p projects/commission-ai-hero/promo.yaml footage add /abs/path/shot-NN.mov --id shot-NN-v2 --shots NN \
      --commit <full app sha> --capture '?demo=promo&...' --framing '1920x1080 CSS at DPR 2, ...' --dpr 2 --demo
```
then point the shot's `source:` at the new id.
